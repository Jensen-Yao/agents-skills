# 通用 CMS 批量刷洞清单(通用型漏洞挖掘)

适用:同一套 CMS 系统被多个站点使用的场景。批量测试的常见出洞点:**备份文件泄露、后台弱口令、未授权访问**。批量结果可考虑按**通用型**漏洞提交(同 CMS 多厂商受影响)。

## 1. 指纹识别与批量找站

**指纹特征采集**(对已知目标站点):

- 路径特征:`/templates/xxx/`、`/static/cms/`、后台路径、目录结构
- meta 标签:`<meta name="generator">`、`X-Powered-By`、CMS 版权注释
- JS/CSS 文件名与路径、favicon hash
- 响应头与报错信息(404/500 页面样式)
- 登录页特征(后台标题、表单字段名)

**批量找同 CMS 站点**:

- FOFA/Quake 语法(用户自有账号):
  - `body="<特征字符串>"`、`title="后台标题"`、`icon_hash="xxx"`、`app="CMS名"`
- 搜索引擎 dork:`intext:"Powered by xxx"`、`inurl:admin/login.aspx`
- 备案主体反查:同主体多个域名通常同 CMS
- 已知 CMS 公开漏洞的受影响资产(如官方演示站列表)

**版本确认**:从页面注释/静态文件头/已知漏洞文件是否存在,确认 CMS 与版本。

## 2. 批量测试项(每站点同一步骤,结果逐站记录)

### 2.1 备份文件泄露

按 CMS 常见路径批量探测(限速 `-t 20`,非破坏性):

- 源码包:`wwwroot.zip`、`web.zip`、`site.zip`、`backup.zip`、`www.rar`、`beifen.zip`
- 数据库:`db.mdb`、`database.mdb`、`data/db.mdb`、`#database.mdb#`、`backup.sql`、`*.sql.gz`
- 配置:`web.config.bak`、`web.config~`、`config.php.bak`、`config.inc.php.bak`、`.svn/entries`、`.git/config`
- 编辑器残留:editor 目录、上传目录、临时文件

命中后验证:确认能下载/还原(如 `.git` 可 dump 源码);**只证明危害,不下载整个库**。

### 2.2 后台弱口令

- 该 CMS 默认后台路径与默认账号密码(查 CMS 文档/公开资料),每站尝试 1~2 个默认口令
- 先看有无验证码/锁定;有验证码则试绕过(万能码、验证码不过期)
- 不跑大字典爆破;证明默认口令可用即可

### 2.3 未授权访问

- 后台/接口免登录直访:`/admin`、管理接口、API 未鉴权(不带 Cookie 重放)
- 编辑器未授权上传:FCKeditor/KindEditor/UEditor 上传接口、文件管理器
- 越权:同套 CMS 接口参数结构相同,可跨站复用测试点(改 id/userid)

### 2.4 已知漏洞核对(可选)

- 版本对应的公开漏洞(如 Nday 的 SQLi/上传/命令执行),在**授权范围内**的站点验证,勿批量利用

## 3. 批量操作规范

- 全程限速、低并发(同目录扫描 `-t 20`);只测**授权范围内**的站点
- 每站点结果记入 `02-scan/candidates.md`(站点、漏洞类型、状态:疑似/已确认)
- 同一问题多站点确认后:提交时说明影响面(列站点清单),评估是否按**通用型**提交
- 证据:每站点截图 + 请求响应原文;敏感信息打码

## 4. 定级与提交

- 备份文件/源码泄露:含数据库或源码可还原 → 中危;仅测试文件 → 低危
- 后台默认口令/弱口令:进入后台 → 按后台权限定级(通常中危)
- 未授权访问核心数据 → 高危;一般未授权 → 中/低危
- 通用型提交:同一漏洞影响多家使用该 CMS 的厂商,可在报告说明"通用型",按平台通用型规则提交
